# Инструкция для Cursor: форма онлайн-оплаты

Результат — набор файлов, которые пользователь кладёт в репозиторий, после чего агент Cursor пишет интеграцию оплаты по безопасной схеме. Ты не пишешь саму интеграцию, а готовишь правила и ТЗ для Cursor (если пользователь просит и код — сделай и его по тем же правилам).

## Входные параметры

Определи из запроса; если не указано — примени значение по умолчанию и явно перечисли допущения в ответе, не задавая вопросов:

| Параметр | По умолчанию |
|---|---|
| Провайдер | Stripe при международной аудитории; ЮKassa для РФ; Przelewy24 для Польши |
| Стек | Next.js (App Router) + TypeScript, Postgres + Prisma |
| Схема | одностадийная оплата, встроенный виджет/iframe провайдера (не свой ввод PAN) |
| Валюта/сумма | хранить в минорных единицах (integer) |

## Порядок работы

1. Прочитай `references/architecture.md` — универсальные требования (они обязательны для любого провайдера).
2. Прочитай файл выбранного провайдера в `references/providers/` (`stripe.md`, `yookassa.md`, `tbank.md`, `cloudpayments.md`, `przelewy24.md`, `payu.md`). Если провайдера нет в списке — найди его официальную документацию и заполни те же разделы: создание платежа, виджет, вебхук и подпись, идемпотентность, статусы, тестовые данные.
3. Сверь с живой документацией провайдера ключевые изменчивые детали (URL скрипта, имена полей, алгоритм подписи, IP вебхуков). Расхождение — правь по официальной документации и укажи это пользователю.
4. Скопируй шаблоны из `assets/cursor-rules/` и заполни плейсхолдеры `{{...}}`:
   - `payments-core.mdc` — архитектура, запреты, модель данных;
   - `payments-frontend.mdc` — форма, виджет, UX, CSP;
   - `payments-webhooks.mdc` — обработчик уведомлений;
   - `payments-provider.mdc` — блок конкретного провайдера (собери из файла провайдера).
   Формат `.mdc` и типы правил — в `references/cursor-rules-format.md`.
5. Заполни `assets/payment-spec-template.md` → `docs/payments/SPEC.md`: ТЗ с критериями приёмки и тест-планом.
6. При необходимости приложи эталон проверки подписи из `assets/snippets/signatures.ts` (только нужную функцию) в `lib/payments/signatures.ts` и подставь путь в `{{SIGNATURES_PATH}}` — Cursor должен использовать его как образец, а не придумывать алгоритм.
7. Сформируй стартовый промпт для чата Cursor (Agent mode) по образцу ниже.
8. Проверь: нет ли в шаблонах оставшихся `{{`, все ссылки на документацию — официальные URL, секреты только через env.

Готово, когда у пользователя есть: 4 файла `.mdc`, `SPEC.md`, стартовый промпт и список допущений. Функции Т-Банка в `signatures.ts` проверены на примерах из документации; остальные перед использованием сверь с тестовым уведомлением в sandbox.

## Структура выдачи

```
.cursor/rules/payments-core.mdc
.cursor/rules/payments-frontend.mdc
.cursor/rules/payments-webhooks.mdc
.cursor/rules/payments-provider.mdc
docs/payments/SPEC.md
lib/payments/signatures.ts   # если нужен: только функция выбранного провайдера
.env.example            # только имена переменных, без значений
```

Упакуй в zip (или выдай одним Markdown-файлом, если пользователь просит текст), язык — язык пользователя, идентификаторы кода — английские.

## Стартовый промпт для Cursor

```text
Реализуй оплату заказа через {{PROVIDER}} строго по docs/payments/SPEC.md и правилам .cursor/rules/payments-*.mdc.
Работай итерациями: 1) модель данных и миграция; 2) серверный эндпоинт создания платежа; 3) страница оплаты с виджетом;
4) вебхук с проверкой подписи и идемпотентной обработкой; 5) страница результата с опросом статуса; 6) тесты.
После каждой итерации покажи diff и чек-лист приёмки. Не трогай секреты, не логируй тела запросов с персональными данными.
```

## Частые ошибки, которые правила должны запрещать

- Сумма приходит с клиента → сумма считается только на сервере из заказа.
- Заказ помечается оплаченным по `return_url`/`successUrl` → только по проверенному вебхуку или серверному запросу статуса.
- Парсинг JSON до проверки подписи (Stripe требует raw body).
- Повторная доставка вебхука выдаёт товар дважды → уникальный ключ события + переход статусов только вперёд.
- Скрипт провайдера скачан в бандл → грузить только с официального домена.
- Платёжный iframe вложен в свой iframe или зажат CSP `frame-src` (ломает 3-D Secure у Т-Банка).
