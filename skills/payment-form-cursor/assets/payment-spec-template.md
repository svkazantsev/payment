# ТЗ: приём онлайн-оплаты через {{PROVIDER}}

## Цель
Покупатель оплачивает заказ на странице `/checkout/[orderId]` через встроенную форму {{PROVIDER}}; заказ получает статус «оплачен» только после подтверждения от провайдера.

## Окружение
- Стек: {{STACK}}
- Переменные окружения (`.env.example`): {{ENV_VARS}}
- Режимы: test / live — разные ключи и секреты вебхуков.

## Эндпоинты
| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/payments | Создать платёж по orderId, вернуть {{CLIENT_TOKEN_FIELD}} |
| GET | /api/payments/:id | Статус платежа для страницы результата |
| POST | {{WEBHOOK_PATH}} | Уведомления {{PROVIDER}} |

## Итерации
1. Модель данных и миграция (Payment, WebhookEvent).
2. Адаптер провайдера + `POST /api/payments` с идемпотентностью.
3. Страница оплаты с виджетом, CSP.
4. Вебхук: подпись → дедуп → транзакция → ответ.
5. Страница результата с опросом статуса.
6. Тесты и чек-лист.

## Критерии приёмки
- [ ] Двойной клик «Оплатить» создаёт один платёж у провайдера.
- [ ] Сумма с клиента игнорируется.
- [ ] Номера карт не попадают ни в наш код, ни в логи (проверено поиском по логам).
- [ ] Вебхук с неверной подписью/IP → 4xx, статус не меняется.
- [ ] Повтор вебхука ×3 → один переход статуса, одно письмо.
- [ ] Возврат на return_url до вебхука → страница дожидается финального статуса.
- [ ] Успех без 3DS, успех с 3DS, отказ — проходят на тестовых картах: {{TEST_CARDS}}.
- [ ] Секреты только на сервере; `.env.example` без значений.
