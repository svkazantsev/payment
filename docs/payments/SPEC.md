# ТЗ: приём онлайн-оплаты через ЮKassa и Т-Банк

## Цель
Покупатель оплачивает заказ на странице `/checkout/[orderId]` через встроенную форму ЮKassa или Т-Банка. Заказ получает статус «оплачен» только после подтверждения от провайдера.

## Окружение
- Стек: Next.js (App Router) + TypeScript, Postgres + Prisma.
- Переменные окружения — `.env.example`. Тестовые и боевые ключи разные.
- Правила для Cursor: `.cursor/rules/payments-*.mdc`.

## Эндпоинты
| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/payments | Создать платёж по `orderId`, вернуть `confirmation_token` (ЮKassa) или `paymentUrl` (Т-Банк) |
| GET | /api/payments/:id | Статус платежа для страницы результата |
| POST | /api/webhooks/yookassa | Уведомления ЮKassa |
| POST | /api/webhooks/tbank | Уведомления Т-Банка |

## Этапы
1. Модель данных и миграция (`Payment`, `WebhookEvent`).
2. `lib/payments/types.ts` + адаптеры `yookassa.ts`, `tbank.ts`; `POST /api/payments` с идемпотентностью.
3. Страница оплаты с виджетом выбранного провайдера, CSP.
4. Уведомления: подлинность → дедупликация → транзакция → ответ.
5. Страница результата с опросом статуса.
6. Тесты (unit для подписей и маппинга статусов, интеграционные для роутов) и чек-лист.

## Критерии приёмки
- [ ] Двойной клик «Оплатить» создаёт один платёж у провайдера.
- [ ] Сумма из запроса клиента игнорируется.
- [ ] Номера карт не попадают ни в код, ни в логи.
- [ ] Уведомление ЮKassa с чужого IP → 403; статус берётся только из `GET /v3/payments/{id}`.
- [ ] Уведомление Т-Банка с неверным `Token` → 400; с верным → ответ `OK`.
- [ ] Повтор уведомления ×3 → один переход статуса, одно письмо.
- [ ] Возврат на страницу результата до уведомления → страница дожидается финального статуса.
- [ ] Успех без 3DS, успех с 3DS и отказ проходят на тестовых картах (ЮKassa: `5555555555554444`, `5555555555554477`, `5555555555554600`; Т-Банк — карты из документации тестового терминала).
- [ ] Тест `tbankToken` совпадает с примером документации: `72dd466f8ace0a37a1f740ce5fb78101712bc0665d91a8108c7c8a0ccd426db2`.
- [ ] Секреты только на сервере.

## Вне объёма
Рекуррентные платежи, двухстадийная оплата, СБП как отдельный сценарий, личный кабинет возвратов.
